# 问题受理模板（你提问时给我这些）

> 不需要写满，给到哪一层我就能答到哪一层。列在越前面，价值越高。

## 1. 必须有的四样

| 项 | 为什么 | 例子 |
| --- | --- | --- |
| 机型 | 决定取哪套参数基线 | 四轴 FJ5 / 六轴光伏清洗版 |
| 固件版本 | 参数名与行为随版本变 | ArduCopter 4.5.7 |
| 现象 | 决定走哪条诊断路径 | 定点模式画圈，半径约 1 m |
| 完整参数导出 | 我能跑体检、做 diff | `.param` 文件或参数表 |

## 2. 加分的三样

| 项 | 作用 |
| --- | --- |
| 日志（`.bin` / `.log`） | 从"可能"变成"确认" |
| 最近改动 | 定位引入点（换了桨、改了参数、装了新设备） |
| 环境与载荷 | 风、温度、载重、水量 |

## 3. 现象描述模板

```
模式：Loiter / Auto / AltHold …
阶段：起飞 / 悬停 / 巡航 / 降落
表现：画圈 / 下沉 / 抖动 / 偏航漂 / 响应迟钝
幅度：± 多少米 / 多少度
频率：高频（>10Hz）/ 中频 / 低频（<1Hz）
可复现：每次 / 偶发（几次一遇）
关联因素：与油门、载重、温度、风向有关吗
```

## 4. 我会怎么处理

1. **参数体检**（`param_audit.py`）：先排掉配置类硬伤；
2. **参数 diff**：与基线或另一台机对比，找异常项；
3. **现象分型**：按诊断树定位到控制层；
4. **证据核对**：有日志看波形，没日志给可验证的判据；
5. **最小改动集**：1–2 个参数 + 方向 + 步长 + 回滚；
6. **验证与入库**：同一动作复飞，结果写进案例库。

## 5. 没有日志时我会怎么说

我会明确标注「这是假设，需要 X 证据才能确认」，并给出验证方法。不会把推测说成结论。

## 6. 一句话版本

```
机型 + 固件版本 + 现象（模式/阶段/幅度/频率）+ 参数文件 [+ 日志]
```

给我这一行，就能开始。
