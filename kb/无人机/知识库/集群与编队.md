# 集群与编队

> 单机问题的解法是调参，集群问题的解法是**架构**：谁决策、谁通信、谁兜底。

## 1. 三层结构

```
任务层   任务分配、航线规划、冲突消解
   ↓
编队层   队形保持、相对定位、避碰
   ↓
单机层   姿态/位置控制、失效保护
```

集群不是「很多架一起飞」，而是**三层解耦**：任务层可以慢（秒级），编队层要快（10–50 Hz），单机层最快（400 Hz+）。

## 2. 编队控制方法

| 方法 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 领航-跟随 | 从机跟踪主机相对位置 | 实现简单 | 误差沿链条累积 |
| 虚拟结构 | 全体跟踪一个虚拟刚体 | 队形稳定 | 需要全局同步 |
| 一致性（consensus） | 邻居状态加权平均 | 去中心化 | 收敛速度受拓扑影响 |
| 势场法 | 引力/斥力合成 | 天然避碰 | 易陷局部极小 |

工程上最常用「领航-跟随 + 相对定位（RTK/UWB/视觉）」，因为它可落地。

## 3. 相对定位

| 方案 | 精度 | 条件 |
| --- | --- | --- |
| RTK 差分 | 厘米级 | 需要基站/网络 RTK |
| UWB | 10–30 cm | 视距、基站布置 |
| 视觉/动捕 | 毫米级 | 室内、光照可控 |
| 纯 GPS | 米级 | 队形间距必须远大于误差 |

**队形间距的经验下限**：≥ 3–5 倍相对定位误差。米级 GPS 想飞 2 m 间距，等于随机碰撞。

## 4. 通信与时间同步

- **拓扑**：星型（地面站转发）简单但单点；Mesh 去中心但时延不确定；
- **带宽**：N 架飞机的心跳与状态消息会线性增长，MAVLink 需要裁剪（只发位置/状态）；
- **时间同步**：编队控制依赖同一时间基准，PTP/GPS 秒脉冲优于软件时间戳；
- **失联降级**：从机失联 → 悬停/返航；主机失联 → 指定继任者或全体返航。

## 5. 冲突与安全

| 风险 | 措施 |
| --- | --- |
| 机间碰撞 | 几何避碰（速度障碍）+ 最小间隔 |
| 频谱拥塞 | 频道分配、TDMA、功率控制 |
| 单点失效 | 去中心化决策、继任协议 |
| 群体失控 | 全局急停（kill switch）、地理围栏 |
| 空域冲突 | 高度分层、时间窗调度 |

## 6. ArduPilot 侧的可用能力

- 多机同场：不同 `SYSID_THISMAV`，不同数传频点；
- 跟随模式（Follow）与编队脚本（Lua）；
- SITL 多实例仿真，可在单机验证编队逻辑；
- MAVLink 路由（mavlink-router / MAVProxy）做多机汇聚。

## 7. 工程指标

| 指标 | 含义 | 典型目标 |
| --- | --- | --- |
| 队形保持误差 | 实际间距与期望间距的偏差 | < 定位误差 × 1.5 |
| 收敛时间 | 扰动后恢复队形的时间 | < 5 s |
| 通信丢包率 | 链路质量 | < 5% |
| 任务完成率 | 成功架次/总架次 | 按场景定义 |

## 8. 现实提醒

集群的难点不在算法，在**测试成本与安全**：N 架飞机的联合调试成本是 N²，任何一次碰撞都可能终止项目。建议顺序：SITL 多机 → 2 机实飞 → 4 机 → 扩展，每步都设最小间隔与急停。
